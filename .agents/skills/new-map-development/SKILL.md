# 新地图开发

从仓库根目录使用本技能，代码路径均相对仓库，不依赖原开发者盘符。遵循根目录 `AGENTS.md` 的确认、预算和集成规则；已有明确回答与授权直接记录，只补问缺口。

## 1. 确认本次交付

先复述地图名、玩家可演示行为、范围与验收，取得确认后再盘点。区分需求清单、设计/生图、地图接入、怪物接入、完整地图闭环；仅确认整理资料不授权实现。

收集需求时读[确认与资料表](references/intake.md)。先问影响范围的缺口，不一次索要全部工程参数。每项标记“已确认 / 待确认 / 不适用”，素材另记“已提供 / 复用已定位 / 待制作”。“沿用现有”须注明具体对象和规则，经代码核对再采用；“你来设计”先给方案供确认。

完成条件：知道做什么、不做什么、缺少资料由谁提供。未定项有具体问题，不能把空白当作无怪物、无奖励或默认数值。

## 2. 核对实现和材料

目标确认后读取 `docs/game_outline.md`、`project.godot`，记录 Git 分支、提交和工作区改动。读[实现定位与验收](references/implementation.md)，再按涉及功能读取原文件。该参考是导航，当前代码和最新验收优先于历史票据。

给出三份短表：已确认需求、缺失材料、拟复用/修改位置。工程路径、区域标识、坐标换算和调用方由代理查找，用户提供设计决策和素材来源。点位标注至少区分玩家通路、怪物活动区、障碍、入口与返回点；合法坐标需要身体/脚底半径及可达路径验证。

完成条件：每个授权行为都有接入位置和验收方法；缺图、缺动作、缺规则分别列明。未把静态立绘当完整动画，未把历史通过当当前能力通过。

## 3. 按授权制作与接入

- 生图按 `AGENTS.md` 设计图规则，首次展示完整实际提示词，覆盖画风、准确文字、尺寸、透明背景与切图要求；确认后执行。同批重试和用户直接改稿沿用已有授权。仅批准素材设计时交设计稿，接入沿用此前明确范围。
- 实现前确认允许修改位置与可独立演示的票据。需要拆分时按玩家闭环拆分、列出阻塞依赖，避免按数据、界面、测试拆成不能演示的任务。创建任务须符合当前环境授权及项目协议。
- 地图闭环覆盖入口确认→实际移动/交互→返回→重进恢复；怪物闭环覆盖发现→追击/攻击→击败/捕获→奖励→跨图/重启恢复。只执行已确认部分。
- 修改界面先读 `docs/ui_component_library.md` 和对应组件。新增游戏任务先读 `docs/quests.md`，确认类型、触发和完成条件，再同步目录与所需迁移。新增地图不自动授权剧情、任务或料理。

完成条件：授权内容已落入目标工作区，素材、状态和界面通过真实调用连接。独立分支交付或孤立显示属于中间状态。

## 4. 验收与交付

按参考验收矩阵选受影响场景，用隔离存档保存命令、报告和真实截图。无头启动不能代替视觉/输入验收，同进程重载不能冒充跨进程恢复。旧测试若验证废弃玩法，先核对现行需求再选用。

交付实际路径、改动、测试结果、未验证项和限制。未达到本次标准写“未完成”。纯资料任务交付完整确认表、材料责任、代码定位和验收方案，不要求运行游戏，也不宣称玩法已经验证。

调用示例：`使用 $new-map-development，为新地图整理开工前要确认的事项和素材清单，先不实现。地图暂定为……`
