# CH1-LIFE-PRE：预卡牌生命周期契约

本票只覆盖第一章从苏醒到准备同行的恢复、兼容、跳过与开发重播。准备同行仍然是 `ready_to_depart`，卡牌为 `pending_content`（内容待提供），不代表第一章最终完成。本票不发放章节奖励、不解锁卡牌、不进入迷宫，也不新增或设置两个最终完成标记。

## 阶段与恢复

“生命周期阶段”指 `SaveManager.lifecycle_stage()` 返回的恢复位置。开场新增 `chapter_1_intro` 字段；经营阶段直接从既有事务、库存及进度推导，避免另存一个会与真实订单矛盾的标记。

| 阶段标识 | 含义及恢复入口 |
| --- | --- |
| `not_started` | 尚未完成苏醒对白，从第一句开始 |
| `awakened` | 苏醒对白已确认并保存，恢复客人入场过场 |
| `guest_arrived` | 客人已登场并保存，恢复客人的第一句对白，恢复唯一客人而不重播镜头 |
| `order_accepted` | 真实接单已提交，从仓库取料开始 |
| `ingredients_collected` | 已领取食材且库存满足制作，从料理台开始 |
| `dish_ready` | 制作已提交且持有成品，从前台交付开始 |
| `order_served` | 首单已结算且库存清空，从准备同行中尚未确认的步骤继续 |
| `ready_to_depart` | 完整且一致的预卡牌准备态，隐藏引导 |

苏醒、入场检查点只在保存成功后推进。写盘失败保留原步骤与数据；客人入场重试先回收旧演出，避免重复角色。经营事务仍使用原有接单、领取、制作、交付方法，数量、奖励和提交顺序保持原规则。

## 准备态结构与兼容

“准备态一致”要求 `chapter_1_departure`（准备同行状态）字段齐全且类型正确，步骤与已发生效果相符。只有检查仓库后才能设置仓库检查标记，只有地图线索确认后才能解锁第一层旧盐池，只有自报姓名后才能显示姓名，只有最终约定确认后才能加入芽芽和铁山、设置精确目标并点亮入口。其他区域保持迷雾，卡牌对象必须严格等于未解锁的待提供状态。

非初始准备步骤还要求规范的已完成首单、结算凭证、已领取标记、收束进度、三个首单库存数量均为零且声望至少包含该笔结算。JSON 数值允许整数或等值浮点，字符串数字不能冒充数量。

正例：通过真实事务与逐句确认达到准备态，退出重进后地图、队伍、目标、入口一致。反例：只写 `step=ready_to_depart`，缺少队伍，卡牌提前解锁，或者地图迷雾为数组，都不能作为就绪证据。

无效准备结构返回安全的 `relief`（收束第一句）视图，并写入去重后的中文 `migration_diagnostics`（迁移与恢复诊断）。读取时先检查原始事务结构，再执行既有库存默认化，不能把错误库存归零后误认为就绪。有效经营数据与未知顶层字段保留；读取本身不重写磁盘、不补发奖励。旧档缺字段、损坏 JSON、非字典顶层及错误完成标记类型都有诊断。无法从矛盾经营状态安全恢复时保留经营数据并回到较早引导，不猜测或补发丢失材料。

既有合法最终完成标记的兼容处理不属于本票的最终完成证明；本票验证的八阶段样例均保持两个最终完成标记为 false。

## 跳过与重播不变量

`skip_all()`（跳过本次引导）只取消运行：先使旧异步令牌失效，关闭普通/空库存仓库和地图弹窗，释放教程拥有的输入锁，恢复镜头，删除临时客人，清理引导与订单追踪显示，以及步骤、角色和引导引用。跳过前后的公开 `SaveManager.data` 与 `save.json` 指纹必须完全一致。重新进入场景仍按已有检查点恢复。

`--replay-tutorial`（开发重播参数）允许准备态重新体验完整序列。`begin_replay()` 创建独立默认内存副本；内部 `_state`（当前事务工作状态）与所有查询及原事务方法一起切换到该副本。重播时 `save()` 只确认内存事务，不访问磁盘。原公开 `data` 全程不替换、不先写后还原。乱序事务仍失败。正常结束、跳过和场景重新启动均释放副本，正常结束刷新订单卡为原经营状态。

正例：原存档为已取料状态，重播中真实领取、烹饪、交单，但原材料和订单始终不变；退出重播后显示原取料状态。反例：重播直接把教程索引移到末尾、临时替换公开数据后还原、或者仅在重播结束比较文件，都不足以证明零副作用。

新调用方应通过 SaveManager 查询/事务接口访问当前经营视图；直接读写公开 `data` 不属于重播事务接口。若将来增加经营入口、异步事务或新的持久化写入，必须重新审查副本路由及清理边界。

```powershell
& tools/tests/ch1_life_pre_run_isolated.ps1 -Import -Visual -OutputDir '<报告目录>'
& tools/tests/ch1_05_run_isolated.ps1 -OutputDir '<05报告目录>'

& tools/tests/ch1_07_run_isolated.ps1 -OutputDir '<07报告目录>'
& tools/tests/ch1_08_run_isolated.ps1 -OutputDir '<08报告目录>'
& tools/tests/ch1_09_run_isolated.ps1 -OutputDir '<09报告目录>'
git diff --check
```

新执行器要求 Godot 4.7.2，隔离 `APPDATA`、`LOCALAPPDATA` 与实际 `user://` 路径；场景在路径或隔离标记不符时退出。每个 Godot 子进程最多 120 秒，失败日志保存在报告目录。`-Import` 执行无头编辑器导入；始终执行无头主入口冒烟检查。省略 `-Visual` 可运行无头生命周期套件。

`seed`（真实样例生成）通过生产对白组件、可走站位、玩家交互、仓库选择及原事务生成八阶段快照。八个 `restore-*`（恢复）进程分别载入快照、建立真实餐厅、跳过、重进，并比较内存与磁盘指纹。`corrupt`（损坏矩阵）逐项验证字段缺失、类型和内容矛盾，额外通过真实入口验证损坏地图不会使界面崩溃。`replay`（重播）逐帧比较两种原经营状态下的内存和磁盘 SHA256 指纹，并验证中途跳过、乱序事务拒绝及完整流程。`intro-save-failure`（开场保存失败）用隔离临时文件目录占位复现写盘失败与恢复。

失败时按报告的场景和字段重现，先修正该结构验证或清理路径，再运行对应流程及相关回归；不能通过补造卡牌、完成标记或结算数据消除失败。
