# 餐厅点单技能

先判定本次是普通点单还是任务点单。用户已说明类型时直接采用；未说明且无法从需求确定时只先询问类型。读取[当前实现与复用规则](references/current-implementation.md)，已有信息与已确认授权持续有效，只补问缺失项。

## 普通点单

用户只需提供以下信息：

```text
素材编号：男/女 + 编号
料理：已有料理名称；如为新料理，提供名称、配方原料及数量
出现时机：具体前置事件与先后关系
```

其余沿用当前冒险者点单：显示名“冒险者”、每单1份、每人一次且不循环、统一接单对白、按交付星级的三档餐后评价、头像贴底、对白蒙层、入座等餐料理气泡、原入座/进食/离场流程、订单跟踪与归档。已有料理沿用目录配方及奖励；新料理复用现有奖励规则和配置约束，不让用户补填人物名、专属对白、动画、头像或工程参数，也不自行发明额外奖励。已有规则确实无法确定新菜参数时才提出具体缺口。

素材编号从已确认冒险者素材中查找，沿用对应身份；缺少该编号动作或料理图标时说明具体缺口，按已有授权补齐，不擅自替换人物。只有涉及新的图片生成且尚未授权，才按项目生图规则提交提示词确认。

普通点单仍使用现有订单任务模板记录进度；“普通”表示没有额外角色剧情任务链，不表示取消订单跟踪。用户要求与默认不同的内容时保留明确例外，不为套模板抹掉要求。

## 任务点单

在普通点单的料理、配方与出现时机之外，收集：

```text
人物名：
人物动画与头像：已有素材路径/附件，或指定代理编写关键词生成
详细对白：按段落/顺序列出说话人和台词，包含需要的选项
任务触发：哪一段/哪一句结束或选择哪个选项后，接取什么任务
任务类型：订单 / 探索（按现有模板）
任务内容与完成条件：订单料理与数量，或探索目标/目标区域/实际完成事件
后续衔接：完成后何时继续哪段对白、何时离场或触发下一步
```

用户只给剧情意图而未给详细对白时，先整理对白和触发映射供确认，不直接发明后落地。素材不足且指定生成时，先列实际需要的动画状态、头像及统一画风，编写完整提示词并依项目要求确认后生成；单张人物立绘不能冒充完整动画素材。

把每段对白与业务事件写成明确链条：人物出现 → 对话段落/选择 → 接取订单或探索任务 → 真实完成事件 → 后续对白 → 离场/下一步骤。区分对白开始、句末、整段结束、选项确认，任务只能在指定事件成功后提交。订单任务复用接单与交付结算模板；探索任务复用实际目标验证模板，已有模板标记未实现的目标不能当作现成能力。其他类型仅在用户明确要求时另行核对，不自动改型。

## 实现流程

1. **核对基线与边界**：读取项目 AGENTS.md、经营实现及用户改动，保留已有工作。记录本次类型、素材、料理、触发、对白与任务事件映射；按项目规则完成范围确认。
2. **复用素材与界面**：执行引用文档中的头像、对白蒙层、气泡、星级评价及旧素材保留约定。显示姓名与持久化身份分离，沿用公共组件，不改背包或对白布局。普通顾客与铁山教程有不同状态入口，选择实际使用的路径。
3. **接入闭环**：候场 → 接单 → 入座等餐 → 取料 → 烹饪 → 交付结算 → 餐后对白 → 离场。来客条件精确区分接单、结算、对白结束和离场完成；存档保存累计进度及先后关系，读档/跨天不重刷一次性顾客，失败回滚、不重复扣料或发奖。新料理登记菜谱、库存和图标。
4. **接入任务**：普通点单沿用订单实例及现有模板；任务点单按已确认对白事件串联订单/探索模板。新增或改型时阅读 `docs/quests.md`，同步 `data/quests/catalog.json` 和必要的定义导入/迁移。`server/quest_registry.py` 是导入查询工具，不是每次修改的文件；按实际结构判断是否需要SQL迁移。任务未读由玩家主动展开清除，完成后归档，重进与重复对话不能重复接取或结算。
5. **验收与交付**：按[专项选择](references/current-implementation.md)适配真实场景，覆盖触发正反例、接取时点、料理气泡显示/消失、实际星级评价、对白任务链、保存失败、读档和双分辨率。新增订单必须验证新增案例，旧测试通过数不代替新案例。目标工作区完成集成后交付路径、截图、命令结果及限制。

测试使用隔离存档；临时配置在 finally 中恢复并核验指纹。正式存档指纹变化时保留证据、明确未通过，不推断来源或回退用户存档。仅整理需求或设计稿时不声称已完成接入。
