# CH1-08 首单交付状态契约

本契约只覆盖第一章首单交付和声望结算，不表示阶段 7 剧情或第一章全流程已实现。

## 状态与不变量

`SaveManager.deliver_first_order()`（首单交付事务）只接受规范首单：订单 ID 为 `chapter_1_first_order`，菜品为盐烤岩鬃肉 `salt_grilled_rockmane`，数量为 1，状态为 `in_progress`（进行中）。还必须已领取材料、`first_order_progress.next_step=deliver`（待交付），且库存至少有一份成品。

事务一次性消耗成品 1 份，将订单设为 `completed`（已完成），将 `reputation`（餐厅声望）累加 20，并写入 `first_order_settlement`（首单结算凭证）：

```json
{
  "order_id": "chapter_1_first_order",
  "item_id": "salt_grilled_rockmane",
  "quantity": 1,
  "reputation_awarded": 20
}
```

凭证表达本笔订单已经交付且已经奖励，不能用 `chapter_1_done`（章节完成标记）代替。订单完成状态或有效凭证任一存在，就拒绝再次交付；已完成首单也不能重新接单、取料或制作。

以上状态和 `next_step=chapter_wrap_up`（等待章节收束）经同目录临时文件写入并替换正式存档。保存失败恢复完整内存快照，正式存档保持原样，教程不推进。

例如声望 45、成品 1 的合法交付得到声望 65、成品 0；再次调用不得得到 85。反例是只有 `chapter_1_done=true`、只有提示文字，或有成品但没有完成取料制作进度，这些均不是交付成功依据。

## 交互、展示与恢复

正式教程阶段 6 的前台 E 交互共用玩家最近目标选择器，前台有效距离为 120px，其他设施仍为 95px。距离按设施交互轮廓到玩家脚底碰撞体计算，不是节点中心距离；多个设施可交互时仍选择最近目标。

前台按钮显示“交单上菜”。保存成功后沿用现有订单卡显示完成 1/1、当前材料及成品库存、当前声望；提示为“顾客吃得很满足！ 餐厅声望 +20”。存档事务成功才推进阶段 7。原有交付后两段反馈对白归入阶段 7，恢复时从第一段开始；对白本身不重复奖励。交付不会自动设置章节完成标记。

旧存档缺少新字段时，结算凭证默认空字典、声望默认 0；`migration_diagnostics`（迁移诊断记录）及控制台说明补齐字段且未补发声望。读取保留既有订单、库存、进度和未知顶层字段，不立即改写磁盘。不能为仅有旧教程完成标记的档案追补奖励。

## 验收与修正路线

在 PowerShell 7 中运行：

```powershell
pwsh -NoProfile -File tools/tests/ch1_08_run_isolated.ps1 -Import
pwsh -NoProfile -File tools/tests/ch1_08_run_isolated.ps1 -Visual
```

运行器隔离 `APPDATA`、`LOCALAPPDATA`，核验实际 `user://` 位于隔离目录，并比较真实存档前后 SHA256。`prepare`、`deliver`、`resume`、`resume_again` 四个模式分别启动独立 Godot 进程。覆盖真实开场到首单闭环、各类乱序与重复调用、保存失败、旧档迁移、场景重开和奖励不重复。可视运行另外保存实际渲染截图。

95–120px 的选择器边界检查临时排除其他设施，避免更近设施抢占目标；成功交付验收恢复全部设施后在原地图可走站位按 E。该检查不声称原地图每个 120px 内的位置都必然选中前台。

若保存失败，排除存档目录写入问题后在同阶段重试；若状态不满足前置条件，保持原状态并返回原因。损坏或手工拼接的跨字段矛盾档案不在本票全量修复范围。修改订单结构、奖励值、教程恢复规则或交互选择器时必须重跑本套件及 CH1-05/06/07、订单卡视觉回归。
