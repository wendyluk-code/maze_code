## 领取事务与旧档

`gold`（金币总额）和 `claimed_chests`（永久领取 ID 数组）缺失时默认 0 和空数组；读取只迁移内存、不写盘、不补发。未知顶层字段与未知字符串宝箱 ID 保留，原章节进度保留。金币或领取结构损坏时保留原字段并诊断，暂停宝箱领取，不能静默清零来重复发奖。

`claim_exploration_chest(id, point)`（领取探索宝箱）只接受已完成第一章、处于实际迷宫区域、配置内 ID、合法道路且在交互半径内的站位。重播禁止领取。金币必须为 JSON 可精确表示的非负整数；加奖不得超过 9007199254740991。

成功事务一次提交金币 +100、该 ID 和当前迷宫站位；使用既有同目录临时文件写入再替换正式文件的原子保存。不等待弹窗关闭发奖。任一步保存失败恢复完整内存、保留旧正式文件、箱体与 E 提示仍可重试。重复 ID 拒绝发奖也不重新保存。每份档五箱总计500；新游戏使用独立存档路径。返回餐厅、继续存档不会刷新已领箱。

正例：成功写盘后箱体消失并显示已到账100；反例：先加金币，关闭弹窗才写领取 ID。修正应收敛到一次业务事务，重新运行写入失败、重复领取、读档及新旧档切换测试，不增加另一份界面计数。

## 交互与输入边界

场景每帧统一选择半径内最近一个有效箱体；距离相同仍只选一个。隐藏或已领取箱不参与仲裁。所有宝箱头顶统一使用本票用户 E 图标，远离隐藏；其他 E 不变。箱体靠近时优先处理宝箱，避免同一次 E 同时触发其他交互点。

开箱必须是新按 E，忽略重复回声；成功后锁移动和其他场景交互、隐藏宝箱提示、禁用保存和标题按钮。`LootModal`（宝箱奖励弹窗）复用 `SproutModal` 的局部主题，只展示已成功保存的物品列表；单件居中、多件网格，显示物品图标、名称和数量，不显示余额或快捷键说明。弹窗内 E 无论长按还是新按都不能关闭。Enter、空格、Esc 及“收下”按钮可关闭；不设关闭按钮，Tab 焦点留在“收下”，遮罩阻挡下层鼠标操作。关闭不写奖励，恢复移动；若 E 仍按住，必须先松开再交互。

正例：按 E 开箱后保持按住，弹窗不动；鼠标关闭后仍按住也不触发其他点。反例：开箱按键同时关闭弹窗，或关闭时又加100。修正只涉及宝箱专用输入路由和场景锁，不改通用键帽或其他场景输入。

## 验收入口与边界

`tools/tests/ch2_chest_run.ps1` 统一设置隔离的 `APPDATA`、`LOCALAPPDATA` 和测试用户目录。每次前后计算正式用户目录所有 JSON 存档的指纹并比较；不在主工作区运行。`import`、`smoke`、`state`、`entry_state` 单进程上限4分钟；有渲染的 `flow`、`entry_flow` 上限10分钟，超时终止该进程并保留日志。不存在超过20分钟的命令。

- `state`：真实文件写入失败、完整回滚、五箱累计、重复领取、未知字段、旧档迁移、新档分离、损坏字段和回放限制。
- `flow`：1152×648、1280×720，真实渲染与 `InputEventKey` / `InputEventMouseButton`（键鼠输入事件）。从餐厅走到入口，沿道路逐箱靠近，无玩家传送。每箱保存两帧截图和弹窗截图；验证移动锁、长按、新按、鼠标遮罩、焦点、键鼠关闭方式、继续存档、回餐厅再入。一项独立的相邻箱仲裁夹具临时摆放第二箱后立即还原，不替代五个正式位置的连续行走。
- `entry_state` / `entry_flow`：直接复用既有入口测试，检查完整环路、栅栏、出口、镜头和保存/转场。
- `import` / `smoke`：无头编辑器导入与真实主入口五帧启动；不能替代有渲染操作验收。
