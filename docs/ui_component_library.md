# Sprout Lands UI 组件库（UI-00）

本目录提供一组局部、可实例化的 Godot 4 原生 `Control` 控件。基础组件负责显示与交互，由业务界面组合使用；订单、库存、存档等状态由调用方管理。独立预览仍使用模拟数据。

## 角色显示复用入口

正式场景主角使用[新版主角动画组件](hero_animation.md)，由餐厅和迷宫共同引用。它负责角色显示，不属于本页的 `Control` 界面控件；新增地图从该约定接入，避免重新使用旧静态人物。

## 预览

打开 `scenes/ui/components/ui_component_preview.tscn` 运行独立预览。页面底部状态栏会记录按钮、弹窗、物品格、滚动列表和分类切换的结果；页面顶部明确标注“模拟数据”。预览不接游戏主场景、不暂停游戏、不锁定玩家；项目配置中的自动加载单例仍随引擎启动，预览脚本不使用它们管理业务状态。

## 世界交互、通行确认与短暂提示

战斗菜单的重开与退出确认也直接复用 `destination_confirmation.gd`，分别显示“是否重开战斗？”和“是否退出战斗？”，按钮为“取消／确认重开”或“取消／确认退出”。菜单仅覆盖该实例的文案并响应确认/取消信号；共用组件保留原样，退出确认后仍按原流程进入失败结算，再按E返回。

新增或修改场景交互时，先查本节与组件实现，再决定接入方式。这三种组件组合覆盖“靠近目标 → E或鼠标 → 二次确认 → 执行业务 → 结果提示”；组件只负责展示和输入路由，场景负责距离、锁定、保存和转场。

| 用途 | 现成实现 | 接入方式 |
| --- | --- | --- |
| 道具悬浮交互 | `scenes/ui/interact_button.tscn` | 餐厅已有 `scripts/ui_layer.gd` 管理目标和距离。其他地图使用 `scripts/ui/components/world_interaction_prompt.gd` 包装同一按钮场景，`configure(action, anchor)` 传入动作文案和世界锚点，监听 `activated`。 |
| 通行二次确认 | `scripts/ui/components/destination_confirmation.gd` | 添加到全屏界面根节点，调用 `open_destination(destination)`；监听 `confirmed`、`cancelled`，由调用方隐藏弹窗并恢复原输入状态。餐厅前往迷宫、迷宫返回餐厅及未开放出口使用此组件；餐厅的冒险者之家直接通行。 |
| Toast（短暂提示） | `scripts/ui/components/feedback_toast.gd` | `attach_to(root)` 创建顶部居中实例，`show_message(message, seconds)` 显示，`dismiss()` 收起。复用餐厅章后交互的深色圆角背景、字体、边距和默认3.5秒时长。 |

餐厅“冒险者之家”保持直接通行。餐厅“前往迷宫”点击悬浮按钮或按一次E先显示“是否前往迷宫？”，默认聚焦取消；取消或Esc留在餐厅并恢复输入，不写进度。点击确认前往或松开E后再次按E才启动转场。继续复用餐厅既有距离判定、通行确认组件和 `scene_transition.gd`；迷宫解锁条件在打开确认前及执行转场前均须满足，重复输入不创建重复转场。

悬浮按钮使用原道具E键图标，屏幕高度48像素，不随镜头缩放；位置投影自入口或道具锚点，靠近显示、离开隐藏。鼠标与E进入同一业务处理并重新核对范围；确认框打开时隐藏交互按钮、锁住移动。宝箱专属E图标不属于普通道具按钮的替换范围。

通行确认默认聚焦“取消”；Esc取消、Tab或左右键切换、Enter执行当前焦点。E须松开后新按才确认，长按重复事件不确认；遮罩拦截鼠标，不触发背后交互。取消不保存、不转场、不弹未开放提示。确认水轮工坊后仍在当前地图，才显示“当前区域未开放，以后再来探索吧~”；确认餐厅后先成功保存，再转场。

正例：石门显示“E 前往餐厅”，栅栏显示“E 前往水轮工坊”，二者共用按钮和通行确认。反例：靠近栅栏立即弹未开放提示，或在屏幕底部另写一条E提示。一般内容弹窗仍使用下方 `SproutModal`；通行确认的安全默认焦点与E松键规则由专用组合组件提供。

验收须在1152×648和1280×720运行实际场景，检查锚点随镜头、屏幕尺寸固定、距离显隐、鼠标与键盘、确认/取消、长按防连触、遮罩拦截、输入恢复及保存失败。若风格或行为分叉，修正共同组件或接入方，并重跑餐厅和迷宫回归。新增样式前须先记录现有组件缺口，在本次已确认范围内补齐并登记复用入口。

## 组件 API

### 地图转场 `scene_transition.gd`

文件：`scripts/ui/components/scene_transition.gd`。这是跨场景的共用渐隐渐显遮罩，适用于已经确认目的地的真实地图跳转，当前接入餐厅与迷宫的双向通行。它挂在场景树根部的独立CanvasLayer（画布层），旧场景释放后继续显示；不需要新增自动加载单例。

```gdscript
const Transition := preload("res://scripts/ui/components/scene_transition.gd")
var destination := load(scene_path) as PackedScene
var error := await Transition.change_scene(get_tree(), destination)
```

调用方先完成该入口规定的业务条件和必要保存，再交给组件。餐厅“前往迷宫”须完成二次确认后才启动转场。旧地图渐隐0.28秒，全遮盖时切图，新地图相机与显示就绪后渐显0.34秒。组件锁定两侧玩家的输入与物理移动、消费键鼠和手柄事件，保留人物待机动画及镜头处理；结束时恢复各玩家原有锁定状态，不擅自解锁保存失败或剧情锁定的角色。场景切换失败时揭开原图并恢复其输入，调用方依据返回错误展示现有Toast。空目标直接拒绝，`is_active(tree)`可查询进行状态；转场期间重复请求返回`ERR_BUSY`（忙碌错误），不生成第二层遮罩。

正例：玩家确认“前往迷宫”后淡出餐厅，再淡入迷宫；返回餐厅使用同一组件。反例：为每张地图复制一套遮罩，或把遮罩挂在即将释放的旧场景下；未开放目的地尚无实际切图，不播放假转场。标题菜单及序章演出保留各自流程，本次未接入。

验收使用两分辨率的真实往返：捕获渐隐、渐显中间帧；全遮盖时只切图一次；期间方向键不移动、连按E不重进；结束移除遮罩，移动、通行确认及宝箱弹窗恢复。更换时长、渲染层、输入锁或新增场景接入后重跑上述验收。若发生黑屏或锁定残留，先核对遮罩归属和目标加载结果，修正共同组件后复验双向流程。

- `SproutTheme.icon(index) -> AtlasTexture`：从现有 `assets/ui/all_icons.png` 取 16×16 图标区域。

主题使用现有 `assets/ui/zcool_kuail.ttf` 显示中文，键帽/像素图标使用现有 Sprout Lands 资源。代码只引用资源，不复制或修改下载目录。

### `SproutButton`

文件：`scripts/ui/components/sprout_button.gd`

```gdscript
var button := SproutButton.new()
button.configure("打开", 0)
button.activated.connect(_on_button_activated)
container.add_child(button)
```

`pressed` 是 Godot 原生信号，`activated(button)` 是带按钮实例的简洁包装信号。鼠标、Enter/Space 键盘激活均由原生 `Button` 处理；主题提供正常、悬停、按下、禁用和焦点样式。

### `SproutModal`

#### 共用弹窗外观（UI-FIX-01）

`scripts/ui/components/modal_style.gd` 集中提供 `BACKDROP`（背景蒙层颜色）与 `close_button()`（关闭按钮工厂）。所有现有业务弹窗蒙层使用 `Color(0.08, 0.06, 0.04, 0.72)`，不透明度72%；覆盖通用/存档、仓库、烹饪、获得物品、通行确认、餐厅地图、迷宫地图、入队卡牌和战斗菜单/结算。转场、章节结束、教程聚光与整页底板继续使用各自约定。

关闭按钮继承原生 `Button`（按钮）的鼠标、Tab焦点、Enter/Space激活能力，复用迷宫地图的34号细线×；正常为暖金色，悬停/焦点转亮金，按下转深金，禁用为灰金。所有状态均无底色、边框、描边和额外焦点框；命中区域最低44×44像素，卡牌保留56×48设计尺寸。仅替换既有×关闭按钮，不给原本只设取消/确认/收下的弹窗新增关闭入口。

嵌套弹窗只保留一层完整蒙层：存档编辑显示时，下层 `_overlay.self_modulate.a`（蒙层自身透明度）暂为0，上层关闭后恢复1；战斗确认显示时，菜单 `shield`（输入拦截层）同样只隐藏自身绘制。输入拦截节点仍在，不隐藏下层内容，不修改原焦点循环、默认取消、逐层Esc或恢复逻辑。正例：重命名时下层列表可见，背景不会再次压黑；反例：将蒙层节点隐藏导致鼠标穿透，或降低上层蒙层到另一套透明度。

验收证据位于 `output/ui_modal_unify/`；本票补充运行器 `tools/tests/ui_modal_unify_run.ps1` 隔离用户目录并分别记录环境与项目错误，补充角色簿和样例场景分别为 `ui_modal_unify_home.tscn`、`ui_modal_unify_visual.tscn`。修改样式、命中区、嵌套蒙层或接入新弹窗后，须重新运行1152×648和1280×720实际渲染、鼠标/键盘关闭、确认取消、距离显隐与输入恢复验收。初次迷宫运行虽然257项业务检查通过，但期间正式存档指纹变化来源未确认，该次“正式存档不变”门禁未通过，不能据隔离路径正确推断变化来源。

文件：`scripts/ui/components/sprout_modal.gd`

```gdscript
var modal := SproutModal.new()
add_child(modal)
modal.confirmed.connect(_on_confirmed)
modal.cancelled.connect(_on_cancelled)
modal.closed.connect(_on_closed)
modal.show_modal("标题", "内容", "确认")
```

`show_modal` 打开局部遮罩并把焦点给确认按钮；确认、取消、右上角关闭和 `Esc` 都会关闭，关闭时发出 `closed`。它不调用暂停、不广播全局事件。关闭后遮罩隐藏，焦点由调用方决定。

弹窗底部的取消/确认操作按钮使用 `SproutButton.set_icon_visible(false)` 与 `set_focus_visual(false)`：文字保持居中，不显示业务图标，也不额外绘制绿色焦点框；按钮仍保留 `FOCUS_ALL`，因此 Enter/Space、Tab 和鼠标行为不变。普通 `SproutButton` 默认仍显示图标和主题焦点框。

#### 二级操作弹窗规范

二级操作弹窗指从已有弹窗内发起的短操作，例如重命名、删除前的再次确认。此类操作必须在原弹窗上方叠加较小的居中弹窗；下层保留可见，以便玩家知道正在操作哪一项。整页导航或主流程切换不属于本规范。

- **保留上下文**：下层标题、列表、选中项、滚动位置保持不变，不能隐藏列表或把原弹窗内容替换成编辑表单。上层配局部半透明遮罩，尺寸小于下层，长名称和错误文案应换行。
- **隔离输入**：只有最上层接收操作。遮罩拦截鼠标，下层按钮停用，Tab、Shift+Tab 和方向键的焦点导航限制在上层。点击遮罩不提交、不关闭、不触发下层按钮。
- **安全默认焦点**：重命名打开后聚焦并全选输入框；删除确认默认聚焦“取消”，直接按 Enter 不应删除。
- **逐层关闭**：取消、关闭按钮或 Esc 只关闭最上层，不改变数据，不连带关闭下层。恢复发起操作的控件焦点；该控件已被删除时，转移到下层安全控件（如“取消”）。
- **提交与失败**：成功后关闭上层并刷新下层相关内容，保留仍存在的选中项和滚动位置；滚动位置超出新列表范围时允许夹到有效范围。失败时上层保持打开，保留输入和下层上下文，在上层显示错误并允许重试。提交期间禁用重复操作。

正确示例：存档列表 → 点击行内铅笔 → 上层输入新名称 → 保存 → 原列表显示新名称。反例：把整个存档列表替换成“重命名存档”，或一次 Esc 同时关闭两层。

当前组合实现见 `scripts/ui/save_selection_modal.gd`：复用 `SproutModal` 构造上层弹窗，并由调用方管理下层禁用、焦点循环、业务结果与恢复。基础 `SproutModal` 本身不提供自动弹窗栈；需要等待业务结果的组合应覆盖默认确认即关闭行为。

验收应在 1152×648、1280×720 下检查两层可见及尺寸，执行取消、关闭、Esc、重复打开、鼠标遮罩拦截、键盘焦点循环、默认 Enter 取消删除、成功刷新与失败保留输入。若出现穿透、上下文丢失或两层同时关闭，应修正组合方的输入隔离和关闭路由，再重跑这些场景。修改基础弹窗或焦点导航时需重新验收。

### 角色原图卡牌蒙层 `character_card_art_modal.gd`

文件：`scripts/ui/components/character_card_art_modal.gd`。继承 `SproutModal` 的 `closed`（关闭信号）与 `close_modal()`（关闭方法），用半透明暗幕和完整原图展示收藏。翻页用 `SproutButton`，关闭复用 `modal_style.gd`，不使用大面板、SproutCard或裁切卡图，不改变公共组件默认样式。冒险者之家将整个详情组件挂在页面所属的独立 `CanvasLayer`（画布层）中，层号为主页层号加1；暗幕和卡牌一同位于页签、列表、返回按钮及前景栅栏之上，不依赖背景子节点的 `z_index`（绘制顺序）均为零。画布随主页一起销毁。

## 迷宫小地图（MAP-01）

迷宫入口通过 `scripts/ui/components/maze_map.gd` 接入 `CanvasLayer`（画布层），右上固定显示直径100像素的圆形局部地图，距右边与上边各20像素，没有附加文字。主角保持圆心，取景半径为总图145像素；地图北朝上、随主角平移，方向标跟随转向。`maze_map_button.gd` 只命中圆内，透明四角不拦截点击。绘制层由 `maze_map_view.gd` 复用，坐标映射由 `data/maze/entry_map_projection.gd` 的地标分片仿射规则提供。组件只读取 `maze.player.position`（位置）、`maze.player.facing`（朝向）、`SaveManager.departure_state().map`（既有区域状态）和既有领取查询，不新增迷雾、奖励或存档字段。

地标网格包含左出口原图边界 `(0,695)` 对应总图 `(1155,414)` 的校准点，覆盖玩家可走到的最外沿。缺少该点时，三角网格会漏掉出口附近的细长区域，位置换算误用入口回退值。修改地标或道路范围后，应检查全部可走采样点均有正确映射，并实际走到出口边缘再返回，核对小图与展开图的位置及移动连续性；仅检查迷雾是否露出不能证明位置正确。

展开时复用本库的 `SproutTheme`、`SproutButton` 和 `feedback_toast.gd`；遮罩拦截鼠标并锁住迷宫玩家物理输入，关闭或 `Esc`（退出键）恢复关闭前的输入状态。浅层按钮保持选中，深层按钮只显示“深层暂未解锁”。`shallow_map_fog.gdshader`（浅层迷雾着色器）使用 `entry_map_projection.gd` 生成的共用遮罩，合并真实道路与用户圈定的完整区域（盐池北侧、入口、旧城长廊及枯水渠），圈内地形全亮，圈外用32个总图像素柔化过渡；保留凹边，水轮工坊等圈外区域仍按原规则遮挡。小图、展开图及资源可见性读取同一缓存，未解锁时仍不揭示区域；校准点和边界均使用总图像素，更换底图时须重新核对；默认参数保持餐厅剧情地图原效果。两种视图只显示未领取宝箱，使用用户确认的生成轮廓和纯金色着色；不显示挖掘点，不改变真实采集。宝箱图标含透明留白的绘制尺寸为小图14像素、展开图22像素。圆形视图将边缘资源图标整体留在圆内。

圆形小地图使用接近任务详情展开框的米色框带与约1像素暖棕外边，总框带约3像素。底层投影为18%不透明度的浅暖棕色，扩散8像素、向下偏移2像素，底色透明，避免形成黑色光圈。投影忽略鼠标，圆形点击区域与100像素地图本体尺寸不变；展开时随小地图一起隐藏，不修改公共主题。

### 对白空白点击与烹饪聚焦教学
