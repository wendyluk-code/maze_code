### 地图转场 `scene_transition.gd`

文件：`scripts/ui/components/scene_transition.gd`。这是跨场景的共用渐隐渐显遮罩，适用于已经确认目的地的真实地图跳转，当前接入餐厅与迷宫的双向通行。它挂在场景树根部的独立CanvasLayer（画布层），旧场景释放后继续显示；不需要新增自动加载单例。

```gdscript
const Transition := preload("res://scripts/ui/components/scene_transition.gd")
var destination := load(scene_path) as PackedScene
var error := await Transition.change_scene(get_tree(), destination)
```

调用方先完成该入口规定的业务条件和必要保存，再交给组件。餐厅“前往迷宫”须完成二次确认后才启动转场。旧地图渐隐0.28秒，全遮盖时切图，新地图相机与显示就绪后渐显0.34秒。组件锁定两侧玩家的输入与物理移动、消费键鼠和手柄事件，保留人物待机动画及镜头处理；结束时恢复各玩家原有锁定状态，不擅自解锁保存失败或剧情锁定的角色。场景切换失败时揭开原图并恢复其输入，调用方依据返回错误展示现有Toast。空目标直接拒绝，`is_active(tree)`可查询进行状态；转场期间重复请求返回`ERR_BUSY`（忙碌错误），不生成第二层遮罩。

正例：玩家确认“前往迷宫”后淡出餐厅，再淡入迷宫；返回餐厅使用同一组件。反例：为每张地图复制一套遮罩，或把遮罩挂在即将释放的旧场景下；未开放目的地尚无实际切图，不播放假转场。标题菜单及序章演出保留各自流程，本次未接入。

#### 二级操作弹窗规范

二级操作弹窗指从已有弹窗内发起的短操作，例如重命名、删除前的再次确认。此类操作必须在原弹窗上方叠加较小的居中弹窗；下层保留可见，以便玩家知道正在操作哪一项。整页导航或主流程切换不属于本规范。

- **保留上下文**：下层标题、列表、选中项、滚动位置保持不变，不能隐藏列表或把原弹窗内容替换成编辑表单。上层配局部半透明遮罩，尺寸小于下层，长名称和错误文案应换行。
- **隔离输入**：只有最上层接收操作。遮罩拦截鼠标，下层按钮停用，Tab、Shift+Tab 和方向键的焦点导航限制在上层。点击遮罩不提交、不关闭、不触发下层按钮。
- **安全默认焦点**：重命名打开后聚焦并全选输入框；删除确认默认聚焦“取消”，直接按 Enter 不应删除。
- **逐层关闭**：取消、关闭按钮或 Esc 只关闭最上层，不改变数据，不连带关闭下层。恢复发起操作的控件焦点；该控件已被删除时，转移到下层安全控件（如“取消”）。
- **提交与失败**：成功后关闭上层并刷新下层相关内容，保留仍存在的选中项和滚动位置；滚动位置超出新列表范围时允许夹到有效范围。失败时上层保持打开，保留输入和下层上下文，在上层显示错误并允许重试。提交期间禁用重复操作。

正确示例：存档列表 → 点击行内铅笔 → 上层输入新名称 → 保存 → 原列表显示新名称。反例：把整个存档列表替换成“重命名存档”，或一次 Esc 同时关闭两层。

当前组合实现见 `scripts/ui/save_selection_modal.gd`：复用 `SproutModal` 构造上层弹窗，并由调用方管理下层禁用、焦点循环、业务结果与恢复。基础 `SproutModal` 本身不提供自动弹窗栈；需要等待业务结果的组合应覆盖默认确认即关闭行为。

验收应在 1152×648、1280×720 下检查两层可见及尺寸，执行取消、关闭、Esc、重复打开、鼠标遮罩拦截、键盘焦点循环、默认 Enter 取消删除、成功刷新与失败保留输入。若出现穿透、上下文丢失或两层同时关闭，应修正组合方的输入隔离和关闭路由，再重跑这些场景。修改基础弹窗或焦点导航时需重新验收。

`scripts/ui/components/chest_interact_prompt.gd` 是供宝箱及已确认的迷宫挖掘点使用的 `Sprite2D`（二维精灵）。它从用户指定 `assets/ui/chests/chest_interact_e.png` 取纹理区域，保留原图和透明度，以24原图像素宽绘制在物件上方。默认隐藏，由场景在宝箱与挖掘点之间统一选择最近有效目标后显示。按 E 或左键点击当前图标都交给场景的同一领取入口；组件本身不发奖。

**所有宝箱与本次四处挖掘点头顶统一使用此 E 图标，其他 E 不变。** 不替换餐厅、对话、章节继续、迷宫石门或公共主题默认键帽。多个箱或采集点同时在范围内也只显示一个。正例：合法道路靠近未领取物件显示，离开隐藏；反例：把素材换入公共按钮默认图标，或多个物件各自响应同一次 E。

验收运行宝箱有渲染流程，检查近/远、相邻目标、原石门与餐厅提示。若出现多个提示或重复交互，修正场景目标选择；若其他 E 改变，恢复公共组件，只保留宝箱局部取图。

### 通用获得物品弹窗

`scripts/ui/components/loot_modal.gd` 继承 `SproutModal` 的关闭信号与行为，使用浅色底及与餐厅仓库一致的细线圆角外框（SproutTheme.thin_panel_style：2像素棕色描边、7像素圆角），确认按钮直接使用 SproutButton 默认样式。界面仅保留“获得物品”、物品图标/名称/数量、“收下”，不设关闭按钮，不显示金币总额或快捷键说明。物品图标为43×43像素，与料理选择图标等宽；不使用厚重纹理外框或绿色按钮覆盖；thin_panel_style 是可复用的组件库样式，不改变原有 panel_style 默认值。

`show_items(items: Array[Dictionary])`（展示物品列表）接收每项的 `name`（名称）、`quantity`（数量）和 `icon: Texture2D`（图标纹理）。调用方提供非空列表、有效图标和已成功领取的正整数数量。单件居中，最多三列；超过两行可用鼠标滚轮或滚动条查看，长名称换行。再次打开会清除上一批内容并回到顶部。不同物品均使用此模板，不新增专属金币弹窗。

```gdscript
var rewards: Array[Dictionary] = [
    {"name": "金币", "quantity": 100, "icon": LootModal.coin_texture()},
    {"name": "材料名称", "quantity": 3, "icon": material_texture},
]
loot_modal.show_items(rewards)
```

`show_reward(amount, total)`（金币兼容入口）仍可调用；内部转为单件物品列表，`total` 仅兼容旧调用，不显示余额。金币图标继续使用用户提供原图的纹理区域。组件不读写库存或存档，也不自行发奖；调用场景监听 `closed`（关闭信号）恢复输入。正例是成功保存奖励后展示；反例是在“收下”按钮回调中再次发奖。

E 无论新按或长按都只消费；Enter、空格、Esc 或“收下”可关闭，Tab 焦点始终留在“收下”按钮。场景打开时锁移动、禁用下层按钮，关闭时仍须遵守 E 松开再交互的规则。

运行 `ch2_chest_run.ps1 -Mode flow` 检查1152×648和1280×720：金币单件、混合物品、长名滚动、重复打开清理、输入隔离和存档不变。混合物品只是隔离验收样例，不改变当前每箱100金币的正式奖励。修改公共弹窗、输入或布局后重跑此流程；出现其他 E 改变时恢复公共组件。完整领取规则见 [第二章探索宝箱契约](ch2_chest_contract.md)。

## 迷宫小地图（MAP-01）

迷宫入口通过 `scripts/ui/components/maze_map.gd` 接入 `CanvasLayer`（画布层），右上固定显示直径100像素的圆形局部地图，距右边与上边各20像素，没有附加文字。主角保持圆心，取景半径为总图145像素；地图北朝上、随主角平移，方向标跟随转向。`maze_map_button.gd` 只命中圆内，透明四角不拦截点击。绘制层由 `maze_map_view.gd` 复用，坐标映射由 `data/maze/entry_map_projection.gd` 的地标分片仿射规则提供。组件只读取 `maze.player.position`（位置）、`maze.player.facing`（朝向）、`SaveManager.departure_state().map`（既有区域状态）和既有领取查询，不新增迷雾、奖励或存档字段。

地标网格包含左出口原图边界 `(0,695)` 对应总图 `(1155,414)` 的校准点，覆盖玩家可走到的最外沿。缺少该点时，三角网格会漏掉出口附近的细长区域，位置换算误用入口回退值。修改地标或道路范围后，应检查全部可走采样点均有正确映射，并实际走到出口边缘再返回，核对小图与展开图的位置及移动连续性；仅检查迷雾是否露出不能证明位置正确。

展开时复用本库的 `SproutTheme`、`SproutButton` 和 `feedback_toast.gd`；遮罩拦截鼠标并锁住迷宫玩家物理输入，关闭或 `Esc`（退出键）恢复关闭前的输入状态。浅层按钮保持选中，深层按钮只显示“深层暂未解锁”。`shallow_map_fog.gdshader`（浅层迷雾着色器）使用 `entry_map_projection.gd` 生成的共用遮罩，合并真实道路与用户圈定的完整区域（盐池北侧、入口、旧城长廊及枯水渠），圈内地形全亮，圈外用32个总图像素柔化过渡；保留凹边，水轮工坊等圈外区域仍按原规则遮挡。小图、展开图及资源可见性读取同一缓存，未解锁时仍不揭示区域；校准点和边界均使用总图像素，更换底图时须重新核对；默认参数保持餐厅剧情地图原效果。两种视图只显示未领取宝箱，使用用户确认的生成轮廓和纯金色着色；不显示挖掘点，不改变真实采集。宝箱图标含透明留白的绘制尺寸为小图14像素、展开图22像素。圆形视图将边缘资源图标整体留在圆内。

圆形小地图使用接近任务详情展开框的米色框带与约1像素暖棕外边，总框带约3像素。底层投影为18%不透明度的浅暖棕色，扩散8像素、向下偏移2像素，底色透明，避免形成黑色光圈。投影忽略鼠标，圆形点击区域与100像素地图本体尺寸不变；展开时随小地图一起隐藏，不修改公共主题。

主角方向标使用用户确认的 `assets/ui/maze_map/player_direction.png`，是金黄分面、米白边与浅棕短投影的手绘卡通箭头。源图朝上，旋转补偿四分之一圈后跟随角色朝向；小图和全图的含留白绘制尺寸分别为23和48像素，停步保持最后朝向。保留原生成透明度和色彩，使用缓存的多级缩小纹理，不再额外绘制旧三角或描边。素材生成说明见该目录 `README.md`。

圆形视图不显示地图地名或深色名牌。它使用 `assets/ui/maze_map/shallow_floor_no_labels.png` 的去字地形，通过着色器只替换原图十二个名牌范围并柔化接缝，范围外仍采样原图；门、桥、水晶等地标图形保留。展开全图继续使用原始带地名地图，迷雾与资源可见性规则不变。源地图文字是图片像素，替换地图时须同步校准名牌范围与无字底图。

迷宫场景的交互提示容器排列在地图控件之后、奖励与通行确认之前，确保通行E按钮绘制和鼠标命中均优先于圆形小地图。宝箱和挖掘E提示也复用原实例移入该容器，在绘制前按原世界变换投影，保留原尺寸和镜头缩放。打开全图或其他模态界面时仍由既有距离与输入锁规则隐藏提示。验收须点击真实重叠区确认触发交互，再从露出的地图区域展开全图，不能假设圆心始终可点击。

左上直接实例化餐厅 `order_tracking.gd`（当前任务组件），保留原有折叠入口、文案、红点与主动展开后标记已读的行为，不修改公共组件。迷宫组合方通过父容器隐藏、禁用入口及暂停该组件输入，在展开地图、通行确认、奖励和转场期间收起任务详情，关闭后恢复入口。

### 对白空白点击与烹饪聚焦教学

玩家主动按“结束烹饪”（鼠标或空格）后，CookingModal 立即锁定落点并保存料理，原烹饪界面继续显示1秒，之后调用现有 CookingResultPopup 显示料理结果。停留期间指针和倒计时不动、输入被拦截；关闭或重开清除等待，旧结果不能延后弹出。保存失败仍保留原落点供重试，成功后才计时；倒计时耗尽的自动结算沿用原展示时序。运行 cooking_countdown_run.ps1 验收1/2/3星定格、半秒切换、连点隔离、保存失败重试与关闭重开。

## 章末标题、说明与顺序渐显（CH-END-01）
