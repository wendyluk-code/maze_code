# CH1-09 准备同行状态契约

本票据接在真实首单交付之后，止于 `ready_to_depart`（准备出发）。它不是第一章完成态，也不开放迷宫探索。设计依据为 `docs/game_outline.md`，具体对白及边界以已确认的 CH1-09 票据为准。

## 状态与不变量

`SaveManager.departure_state()` 返回 `chapter_1_departure`（第一章出发准备）的独立快照。准备流程要求首单完成、结算凭证存在、经营进度为 `chapter_wrap_up`（首单后收束），且岩鬃肉、岩盐、盐烤岩鬃肉均为零。失败事务不改变内存或正式存档。

| 字段 | 定义与提交时机 |
| --- | --- |
| `step` | 下一项未确认步骤的稳定标识。`WRAPUP_STEPS` 的标识与顺序属于存档契约，不使用易变的场景步骤下标作为存档。 |
| `empty_warehouse_checked` | 玩家在仓库范围内按 E 打开现有仓库组件，并确认真实零库存后为 true。 |
| `map.unlocked_floors` | 铁山提供旧盐池线索后为 `[1]`，查询返回整数楼层。JSON 读取的浮点数字转换为整数，保证跨进程一致。 |
| `map.visible_regions` | 同时写入 `["old_salt_pool"]`（旧盐池）。 |
| `map.other_regions` | 固定 `fog`（迷雾）。不生成其它区域或完整迷宫。 |
| `tieshan_name_revealed` | “我叫铁山，是个冒险者。”确认后为 true；该句仍显示“？？？”，随后使用“铁山”。 |
| `party` | 最后一句同行约定确认后写入 `["yaya", "tieshan"]`（芽芽、铁山）。 |
| `objective` | 与队伍一起写入“与芽芽、铁山一同进入迷宫浅层”。 |
| `entrance_lit` | 与队伍一起设为 true；餐厅左侧门出现光圈，E 只查看地图与队伍，不切换场景。 |
| `cards` | `status=pending_content`（内容待提供）、`unlocked=false`（未解锁）、`card_ids=[]`（无卡牌）。本票据不提供正式卡牌。 |

每次 `advance_departure(expected_step)`（完成预期步骤）只允许从当前步骤推进一次，步骤变化及对应状态在同一个存档提交。对白逐句确认后保存：已经确认的句子不重播，尚未确认的句子允许重播。重复旧步骤、提前调用后续步骤、远距离和错误目标交互都不能取得解锁。

正例：旧盐池对白确认后，存档同时出现第一层解锁与 `map_review`（查看地图）检查点；重进打开地图确认面板。反例：仅设置章节完成布尔值、发 Toast（短暂提示），或未检查仓库直接确认同行，均不构成准备成功。

## 恢复与章节边界

`TutorialManager.start()` 与 `TutorialGuide.should_start_chapter_1()` 均检查准备态。`ready_to_depart` 时隐藏教程并恢复玩家输入，不重播第一阶段；HUD 展示目标、队伍查看入口及卡牌等待状态。`chapter_1_done` 与 `tutorial_done` 对正常新档保持 false，也不发出章节完成信号。

本票据新增空仓库与地图弹窗在取消当前教程时会关闭并恢复输入，保存的检查点不丢失。旧版已经写入完成标记的存档、损坏的准备字段、完整开发重播与全章节跳过矩阵由 CH1-11 统一处理，不在此处推断迁移或补发任何经营奖励。

CH1-10 仍阻塞于芽芽/铁山的 16 张正式卡牌内容。CH1-11 负责最终生命周期与章节完成提交。序章、迷宫探索、战斗与第二章均未完成，不能将本票据验收称为第一章最终验收。

## 展示资源边界

空仓库复用 `WarehouseModal`、`SproutTheme`、`SproutItemSlot` 和 `SproutButton`。地图使用相同组件库的区域状态文字面板，明确显示旧盐池可见、其余迷雾；它不是正式迷宫美术资源。入口光圈由脚本绘制在现有餐厅左门上，无新增大型美术资产。“放下盘子”采用剧情提示文字，未新增角色动作素材。

## 验收与修正路线

运行 `tools/tests/ch1_09_run_isolated.ps1`；加 `-Visual` 输出真实渲染截图，加 `-Import` 执行编辑器导入检查。脚本分别启动仓库、地图、同行决定、恢复、再次恢复五个独立进程，最后运行正式主入口冒烟检查。每个命令限时 120 秒，独立 APPDATA/LOCALAPPDATA，前后核对真实存档 SHA256。

测试覆盖逐句对白、姓名时机、错误目标、超距、重复 E、重复领取、保存失败回滚、场景重进、两个独立准备态恢复、地图/队伍/目标/入口一致性与未解锁卡牌。CH1-05～08 及订单卡视觉回归继续运行原有验收脚本。本票据验收使用真实场景、可走站位与玩家交互入口；角色站位由测试助手设置，不等同于人工连续行走录像。

修改步骤标识、地图数据、JSON 读取方式、模态输入锁或正式迷宫入口时，必须重审本契约并运行上述跨进程验收。失败时先对比内存快照、`save.json` 和步骤标识，单独复现保存、恢复或交互失败，不通过改完成布尔值绕过检查。
