# 章后顾客与食材回流规格

2026-10-10 用户补充。此文件记录已确认规则与素材／剧情依赖，不代表尚未提供的三名顾客已进入游戏。

## 到店与容量

- 第一章结束后陆续到店。首位顾客在玩家首次真实进入迷宫后出现；玩家返回餐厅时能看到他在前台等待点单。
- 首访判定必须来自未来正式迷宫的进入成功事件。地图预览的打开、关闭及二次确认不算进入迷宫，不触发顾客。
- 先设计三名顾客，各自保存角色、到店条件、所点料理和餐后对白。第一位触发已确定；第二、三位时机以及三人的形象、菜品、对白待用户提供。
- 点单时按第一、第二、第三把空椅子顺序分配座位。吧台已有三名顾客等待时不出现新顾客。动画及餐后对白期间仍占座，离开完成才释放。
- 首位顾客到店只触发一次；已触发记录持久保存，返回或读档不重复生成。满座时不丢弃等待中的到店条件。

## 共用四类演出

| 动作 | 触发与流程 | 角色差异配置 |
| --- | --- | --- |
| 前台进入 | 到店条件满足且容量允许 → 入场 → 前台等候点单 | 角色立绘／动作、脚底锚点和尺度 |
| 点单后入座 | 成功接单并原子预留最前空椅 → 前台渐隐 → 对应座位渐显入座 → 等待上菜 | 入座素材和坐姿锚点；复用统一渐隐渐显时序 |
| 上菜满意 | 对应料理成功交付并一次结算声望 → 用餐满意动作 | 用餐／满意素材，不在动画回调重复发奖 |
| 餐后离开 | 用餐结束 → 对应角色对话框 → 玩家结束对白 → 离开动作 → 释放座位 | 名字、头像、对白、离开素材 |

共用状态建议为：未到店、前台进入、前台等待、转场入座、吧台等待、用餐满意、餐后对白、离开、已离开。状态必须保存顾客ID、订单ID、座位和演出检查点；重进恢复当前状态，不重复接单、交单或奖励。取消／离树终止旧动画，禁止过期回调推进下一状态。

需要把现有单一当前订单升级为最多三份对应座位的订单；“当前任务”按订单实例展示。不能只复制角色节点而仍让三个顾客共享一份订单。三座椅布局须基于餐厅原图实机校准，首章铁山演出保持独立兼容。

## 食材回流

食材补给只来自迷宫“挖掘”和“战斗”掉落，获得后直接进入仓库，餐厅不定时补货，不因接单发料。具体掉落、时机与数值等待用户提供。未来回流提交应携带唯一事件ID，写入仓库存量与已处理事件记录，重复事件不重复发放；仓库仍遵守30种／每种999的现有容量约定，溢出处理需在接入掉落时确认。

## 本轮落地边界

送餐和冷藏暂统一显示“送餐暂未解锁”“冷藏暂未解锁”，即使声望达到以前的5000／2000也不声称功能已经开放。保留原门槛作为后续设计输入。

迷宫与冒险者之家正式场景、盐池到达事件由用户稍后提供，本轮不开发替代场景。缺少角色配置、动作素材及正式进入／返回事件时，只记录共用流程，不用铁山复制三份充作正式顾客，也不在关闭地图时伪造到店。
