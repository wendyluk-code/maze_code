# 本地隐藏调试工具

使用：在游戏窗口内依次输入78789（相邻数字间隔不超过3秒，支持主键区和数字小键盘），即可打开。没有常驻菜单入口。输入1—1000000的整数，选择增加金币、增加星尘、增加队伍饱腹度，或补满队伍饱腹度。按Esc或点击关闭后可再次呼出。

仅Godot编辑器运行及调试构建启用；正式发布构建由OS.is_debug_build关闭入口和修改接口。数字序列只是隐藏入口，不是身份验证，不应将调试构建当作正式版分发。

修改立即写入当前加载的本地存档。增加饱腹度按输入的全队总量依队伍顺序分配，单人不超过成长后的上限，未出战角色不变；探索中同步capture_run_v1的总量。没有当前队伍时给出提示。重播和序章预览拒绝修改。保存失败恢复完整修改前数据，不迁移、不清空未知字段。

面板为全局Autoload节点LocalDebug，复用SproutTheme、SproutButton和modal_style遮罩。打开时保留原暂停状态、焦点与各节点输入处理开关，临时阻断底层快捷键；关闭后恢复。其他场景沿用原行为，饱腹度、金币、星尘显示沿用既有刷新机制。

2026-10-26验收：目标F:/maze_code。tools/tests/local_debug.tscn在1152×648、1280×720覆盖餐厅和详情，还验证主菜单及实际迷宫，41项通过。使用Input.parse_input_event注入物理键按下/松开，覆盖连续暗号、实际点击加金币、星尘保存读档、饱腹度总量/上限、迷宫HUD、错误暗号、原暂停状态、Esc只关顶层和保存失败回滚。证据output/local_debug/integrated，正式存档指纹未变。系统证书读取警告与项目无关；正式发布构建的运行验证未执行，启用边界由入口和写入接口的同一构建检查保障。

复查条件：更换全局输入处理、模态窗暂停规则、角色饱腹度存储、探索队伍结构或存档接口时，重跑专项并核对原弹窗保留与输入恢复。不要将角色饱腹度与探索总量拆开写入。
