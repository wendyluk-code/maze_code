## 来源与观察边界

参考文件：`C:/Users/KSG/Downloads/xiezuo20261010-221855.mp4`，2388×1668，约149.66秒，可变帧率，标称29.97帧/秒。素材只作观察参考，不把百闻牌画面或音轨打包进游戏。

全片建立0.5秒间隔的299张索引帧；先手翻面、起手替换、收牌、出牌、出击起点与结束回合六个关键窗口另按连续源帧检查。时间轴是画面事件的近似时间，不把可变帧率录像换算成精确的固定帧号。长时间静止查看牌面的片段采用索引检查，没有声称逐张人工查看全片所有编码帧。输出证据在 `output/battle_reference/`：`overview_*`、`detail_*` 和六组连续帧拼图。

视频是触屏录像，没有鼠标按键/触摸事件日志。能直接观察抬牌、大图、拖出、翻面、效果与回合变化；点击与拖拽阈值、取消手势及判定区域是本项目实现选择。录像没有最终胜负画面；胜负结算是沿用参考节奏的补充设计，不能称为录像复刻。未对音轨做逐帧音效分析，当前反馈为本地合成短音。

## 交互与层级

战场采用1280×720设计坐标，在实际窗口中等比缩放。顶部露出的敌方牌背、中央角色、底边重叠手牌、右侧结束回合/牌库和左侧预览彼此职责固定。显示与命中使用同一坐标变换，1152×648和1280×720使用相同输入规则。

准备区和战斗区围绕当前底图荷叶的视觉中心(638,342)布局，该坐标位于1280×720设计画布内。战斗区共享穿过荷叶中心的竖轴：我方中心(638,433)、敌方中心(638,251)，两者中点落在荷叶中心；准备区中心分别为(490,492)和(490,192)。敌方纵坐标统一用684减我方纵坐标，出击槽、箭头与最终站位共用这套位置。完整角色原图显示在116×194区域，不裁头像、不裁透明留白、不叠造卡框；形态切换仍直接显示完整正式形态图。双方战斗区在荷叶中心上下紧邻，原图透明边缘保留。实时生命显示在左侧角落的头像徽章中。底部手牌向右留出角色操作空间，提示放在回合按钮左侧，不覆盖手牌。

| 玩家动作 | 可见反馈 | 提交与取消规则 |
| --- | --- | --- |
| 悬停手牌 | 抬高、转正、放大到1.12倍，左侧显示完整牌与说明 | 不扣牌、不扣行动点；移开收回 |
| 点任意手牌 | 全组展开，当前牌放大，无选中框；最多七张一排，更多牌分两排 | 条件不足也可读牌；拖出立即收起其他牌，合法目标松手出牌后保持收拢 |
| 按住手牌移动超过12设计像素 | 卡面跟随指针，目标曲线与命中圈 | 仅在合法角色上松开才提交；其他位置松开0.18秒回弹 |
| 右键、Esc、点空白 | 收起全部手牌，清除选择、目标线与预览 | 不消耗资源、不进入动画 |
| 按住我方角色 | 立即显示出击箭头、己方战斗槽高亮，拖动时角色轻跟手 | 向上移动至少24设计像素后松手出击，不需要拖到敌方；横向偏移须在120像素内，每回合一次、消耗1行动点 |
| 角色上拖后拖回、原地松开、横拖、下拖、右键或Esc | 箭头消失，角色恢复所属区域 | 以最后松手位置判定；不出击、不扣点，取消后再松开也不提交 |
| 结束回合 | 当前选择收回，按钮禁用，播放敌方回合条 | 动画锁期间不能重复触发，也不能从手牌穿透出牌 |
| 条件不满足 | 牌面灰化，预览/公共短暂提示说明原因 | 保持牌、生命、行动点不变 |

层级：战场→手牌→预览与目标边框→开局/结算暗幕→起手牌/签牌→出牌、目标曲线和局部特效→结算内容→公共短暂提示。开局和结果暗幕拦截下层原生按钮；业务状态另行拦截战斗动作。

## 状态顺序与动画输入锁

`opening（先手演出） → draft（起手调整） ↔ replacing（单牌替换） → dealing（收牌） → turn_intro（回合提示/抽牌） → player_turn（可操作） ↔ resolving（出牌/攻击结算） → ending（回合结束触发） → enemy_turn（敌方行动） → turn_intro`

任何致命伤害在数字与击倒动作后进入 `result（最终结算）`，不得继续调用下一回合。胜负蒙层渐入0.40秒，结果面板缩放0.90→1.00并渐入，提供“再战一场”和“返回主菜单”。该入口来自主菜单，因此不放置没有真实场景承接的“返回探索”按钮。

角色各自持有准备区/战斗区位置状态。开场都在准备区；出击先进入己方战斗槽，再短促后撤和撞击，命中时才改变对局生命。受击抖动与伤害数字并行，攻击者稳定在战斗区后再判断胜负；后续回合保持战斗区位置。敌方使用同一动作和镜像坐标。治疗在卡面落到目标时生效，飘字显示实际恢复量，满血为+0。头像仅显示当前牌手生命，普通对局30/30，当前教学我方10/敌方5；教学和剧情可覆盖各自初始生命。形态更新保留所属区域，不把角色卡的生命上限写入牌手生命。

## 正式牌与演示规则边界

- 使用原有芽芽五种正式卡图与说明，攻击2、温火照料恢复2；原图印刷的角色生命4/5/7不作为牌手初始生命，牌手生命由上述对局配置提供。此演示仍未实现独立的角色受伤/气绝循环。
- “芽芽”只在角色区。手牌由小小掌勺人1、温火照料2、战地小厨1、热锅协作1组成。为展示五张起手、换牌、后续抽牌，独立演示牌库另放同样五张能力牌；这是演示配置，不是正式构筑数量规则，也未改正式卡牌目录。
- 每个我方回合2行动点，出牌和出击各消耗1，出击最多1次；等级仍显示正式说明，当前演示不加入等级升级/气绝循环，也未实现联网PvP，不能称为完整百闻牌规则实现。
- 芽芽出击每回合烹饪一次，小小掌勺人被攻击烹饪，战地小厨仅在位于战斗区时于己方回合结束烹饪，准备区不触发。没有正式食材/佳肴数据，烹饪只增加演示计数，不写库存。
- 热锅协作需要食材与另一名己方角色；此演示只有芽芽一个角色，因此保留卡面和说明、提示条件不足，拒绝支付和出牌。删除旧版“对敌方直接造成2点伤害”的假效果。
- 教学固定起手提供场景导出参数，演示开局另有切换入口；换牌发生后不能改成教学牌组。教学模式不能选择或替换起手牌，但能直接进入战斗。
- 独立演示不接探索入口、存档和奖励；不修改餐厅交互、受保护的距离显隐或角色素材。

## 组件复用与缺口

复用 `SproutTheme` 中文字体、`SproutButton` 的原生按钮激活/禁用/焦点以及 `feedback_toast.gd` 的反馈消息。卡面、扇形手牌、目标连线、签牌与回合圆钮属于公共组件库未覆盖的战斗表现，局部封装在战斗脚本和 `battle_effects.gd`，不改变公共组件样式。卡图直接使用源纹理，`TextureRect`（纹理显示控件）等比完整显示；不使用 `AtlasTexture`（区域纹理）裁图。

## 游戏内验收

1. 运行主场景，点击“卡牌战斗”；也可直接运行 `scenes/battle/yaya_battle_demo.tscn`。
2. 观察上下签牌翻面，再进入起手调整。可直接保留，也可原位替换；第4次换牌应不可用。
3. 确认后手牌直接落入底边，先手方开始；悬停不同手牌查看左侧说明。
4. 把“小小掌勺人”拖到我方芽芽，松手生效。拖到敌方或空白处则退回；右键/Esc可取消。
5. 按住准备区我方芽芽，确认立即出现箭头。向上拖约24设计像素后松手，角色进入战斗区并留场；命中时生命减少、出现烹饪浮字、消耗1行动点。另试原地释放、短拖、拖回、右键和Esc，都应取消。
6. 选中一张牌后点击右侧结束回合，仍应正常交接；敌方演出时不能出牌或重复结束。敌方首轮变形、后续出击进入上方战斗区，双方沿中线正对，准备区和战斗区均上下镜像。
7. 己方受伤后点“温火照料”再点我方芽芽，直接恢复2生命；无需额外确认。
8. 尝试热锅协作，显示条件不足且不消耗。自然完成胜利或失败，检查结算及再战/返回按钮。
9. 再开一局启用教学固定起手，确认不可换牌仍可进入战斗。

可重复验收场景：`tools/tests/yaya_battle_input.tscn`。它从真实鼠标与键盘输入走完整流程，捕获实际OpenGL渲染，最近头像区简化结果输出 `output/battle_clean_hud/report.json`。新增输入路径、窗口缩放或异步状态后须重新执行；无头检查只补充脚本/资源检查，不能代替上述交互验收。
