## 过冰与达标窗口（2026-11-02，覆盖下方旧计时规则）

0–3秒向少冰上涨，3–6秒停留；6–9秒向中冰上涨，9–12秒停留；12–15秒向多冰上涨，15–18秒停留。达到的刻度亮绿线，18秒起最上刻度变红并显示过冰。原蓝色填充和米色空格保留，填充连续上涨。

取出暂停冰镇进度，按最后完整档位交付；重新放入继续原进度，不刷新取杯窗口。过冰取出、重放、读档均保留。点水顾客收到过冰水仍接收，但无小费、基础5金币扣2，实收3金币，不扣声望；满冰需求也不例外。没有点水的顾客仍沿用问号规则。旧档按原完整档位迁移到新时间轴，旧满冰不会因升级立即过冰。新杯标记 chill_revision=2（冰镇计时版本2），不变更铁山首单。

## 玩家操作

普通顾客接单时同时生成料理和甘露水需求。头顶上方是甘露水图标与三格冰度，下方是料理图标；各自交付后独立消失，两项完成才开始吃饭和离场。旧订单缺少饮料字段时按原流程完成，不补单。

到小餐车按 E 打开倒水窗。按住按钮或空格倒水，松手立即结束且不能续倒；关闭正在倒水的窗口、失焦也结束。空中水滴计入已经发出的水量，后续落水动画不改判定。未开始倒水可直接关闭。完成后端起；空杯或不满意的水可到垃圾桶，使用原确认框丢弃。倒水不扣食材。

冰柜解锁后显示三个凹陷杯位。靠近后点击指定杯位放入/取出；E 默认操作第一个空位或第一个已放杯位。手中已有杯子时不能取另一杯。冰镇没有弹窗，杯子旁显示三格温度计与到下一格的秒数；料理保鲜仍可通过旁边的“料理保鲜”按钮进入原界面。

到吧台按 E，手持甘露水时按接单顺序交给第一位尚需饮料的顾客；否则沿用料理交付。冰柜未解锁时需求均为不加冰；解锁后的新订单使用订单序号轮换四档冰度。

## 判定与结算

水位以杯子有效高度计，目标为65%。偏差不随窗口分辨率变化。

| 条件 | 小费系数 |
| --- | --- |
| 水位偏差不超过5个百分点 | 1 |
| 超过5、不超过15个百分点 | 0.5 |
| 超过15个百分点或溢出 | 0 |
| 实际冰度与需求一致 | 1 |
| 冰度相差一档 | 0.5 |
| 冰度相差两档及以上 | 0 |

两种系数取较小值，收入为基础5金币加 `2 × 系数` 小费，即7、6或5金币。偏差仍完成需求，只反馈短暂提示，不扣声望。空杯不能交付。

冰镇累计餐厅运行时间：0至不足3秒为0格、3至不足6秒为1格、6至不足9秒为2格、9秒起3格，不继续增加。暂停及离线不累计。取出后锁定已达到的整数档；再次放入从该档继续。

## 保存与复用边界

`ganlu_service_v1` 保存手持杯、三个杯位和饮料结算凭证。接单、倒水开始/结束、放入、取出、丢弃及交付均保存失败回滚。冰镇进度每秒尝试保存，其他事务也会带上当前进度；异常退出最多损失最近约一秒尚未写盘的冰镇时间。中断的倒水恢复为空杯，不能重新倒入，只能丢弃。料理奖励与饮料奖励各自只结算一次。

新增组件复用 `SproutTheme.panel_style`、`SproutButton`、`modal_style.close_button`、`discard_confirmation`、原 HUD 输入锁及短暂提示。素材来自本次已确认的水彩图素和背景，放在 `assets/ui/ganlu/`。杯槽只取批准图的内托区域，映射到现有冰柜绿色面板，不覆盖周边地图。
