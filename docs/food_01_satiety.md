# FOOD-01 角色饱腹度契约

## 玩家规则

每次捕获尝试消耗一名出战角色1点饱腹度，成功或失败均扣除。按本趟出战顺序轮流查找：从游标开始，跳过不足1点的角色，由首个足额角色承担；游标移动到实际承担者的下一位。所有角色都不足1点时拒绝捕获，即使总量达到1点也不跨成员拼点。拒绝、选择不捕获、退出均不额外扣费；两种离场不返还已经消耗的饱腹度。扣费者与技能触发无关，全部出战成员继续按既有技能条件判定。

个人余额允许小数。迷宫外每秒恢复「自身上限 × recovery_percent / 100」，支持在线与离线，达到个人上限即停止。芽芽初始上限2、恢复率每秒0.020%，从空腹到满需要5000秒，即83分20秒。迷宫期间暂停，退出时建立恢复时间锚点，迷宫停留不能回算为恢复时间。系统时钟回拨不产生负恢复。

每趟从队伍首位开始，趟内游标持久化，重进与读档不重置。队伍顺序只在新趟冻结。当前项目支持的角色仍为芽芽与铁山，本票没有新增角色、换队界面或改变技能、战力、概率、体力与奖励。

## 数据与事务

`character_satiety_v1` 保存逐人 `values`（当前余额）、`at`（UTC秒时间锚点）、`paused`（是否暂停）。`character_progression.gd` 的 `satiety_snapshot()` 只读投影当前恢复值，不因界面刷新写盘。`capture_run_v1.food_version=1` 与 `food_cursor`（下次查找起点）区分新的个人扣除协议。

进场冻结恢复值；捕获余额、游标和掉落与原捕获事务一起原子保存；离场余额、恢复锚点、位置和奖励也共用原有事务。保存失败恢复整个状态，不能发生只扣人不存结果或重复扣除。无需修改 SaveManager 的保存接口。

正常旧3点进行中存档首次恢复时，按「原上限－剩余值」和当趟顺序重建已消耗量，保存成功后登记版本，重复恢复不重复补扣。旧档没有实际逐人付款历史，重建结果代表新规则下的确定性迁移，不能还原此前未记录的历史。

历史70点容量不匹配的进行中探索本趟继续沿用旧池，两个离场入口都按「旧池上限－剩余余额」从出战首位轮转补扣个人余额，最低0；补扣、恢复时间锚点和离场同事务，失败全量回滚，重复退出不会重复补扣。旧档未记录实际付款者，只能按顺序重建。下趟采用真实个人余额，迷宫停留时间不计入恢复。

## 跨会话稳定约束

饱腹恢复读取不写盘；时间锚点必须与位置转换同事务；迷宫内不恢复；游标与付款必须同事务；技能判定遍历全部成员。修改角色上限／恢复率、区域转换、保存接口或队伍组成时重新运行专项。新增换队或新角色体系时重新审查拥有关系与恢复范围，不能直接把当前两人出战记录当作通用角色仓库。
