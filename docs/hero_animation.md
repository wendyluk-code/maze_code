# 正式主角动画复用约定

餐厅、迷宫及后续正式场景统一使用用户确认的新版人物 GIF 转换资源 `assets/characters/hero/animation/hero_animations.tres`。GIF 已按原始帧时长转为 Godot 的 SpriteFrames（逐帧动画资源），无需在游戏内直接解码 GIF。

`scripts/characters/hero_animation.gd` 是共用显示组件。每个角色独立创建实例，进入场景时调用 `install(actor)`，由组件在角色下创建 `Body`（人物）与 `GroundShadow`（脚底阴影）两个 Sprite2D（二维贴图节点）。随后通过 `update(facing, walking, delta)` 传入朝向、是否行走和本帧时间。出生时传入零时间以立即显示；显示帧持续更新，输入锁定或暂停移动时传入 `walking = false`，仍播放待机。

四方向各有独立待机与行走素材，不用镜像代替左右方向；待机4帧、行走8帧，循环保留原时长。帧画布384×360，人物实高300，脚底锚点为(192,332)。人物高度统一取餐厅的130，阴影统一使用 `assets/characters/tieshan/ground_shadow.png`、缩放0.64、脚底偏移(0,1)，全部配置只在共用组件定义。组件负责等比缩放和脚底对齐，不额外叠加上下跳动。

餐厅日常镜头倍率为0.85，人物屏幕高度为110.5像素。迷宫及后续使用不同日常镜头倍率的正式地图设置 `match_reference_view = true`（匹配餐厅显示大小），组件按0.85除以当前镜头倍率换算人物和阴影的显示缩放，相同窗口下显示大小与餐厅一致。餐厅自身保持默认关闭换算，保留剧情镜头的正常放大效果。场景不得自行配置另一份人物高度、阴影或动画；碰撞、道路、速度和交互仍由各自控制器负责。

正例：新地图创建组件实例，复用人物与阴影的完整显示，按实际移动/锁定状态更新显示。反例：从旧原型复制 `hero_front.png`、`hero_back.png`、`hero_side.png`，另写一套换帧计时，或为迷宫单独绘制椭圆阴影、配置人物高度。旧2D/3D原型不属于正式入口，若以后启用也须先接入新版人物。

验收须在实际运行目录检查餐厅进入迷宫、四方向按键移动与换帧、停止后保留朝向待机、锁定时不移动、脚底和道路边界、E交互及返回餐厅。更换素材、锚点、组件或场景接入方式时重新执行 `hero_animation_run.ps1` 和 `ch2_entry_run.ps1 -Mode flow`，查看新截图；若出现旧人物或脚底漂移，先检查场景是否绕过共用组件，再修正引用或锚点并复验。
