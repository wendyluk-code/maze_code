## 3. 根因

原雷鳗共用WaterSpacing.swim与Fenshui.move的完整水域限制，以及通用return回血；TeamAttack伤害与膜显示仅接入正式银鳞鱼。红灯证据分别为red-damage的3项失败、red-shore的缺上岸阶段以及red-visual的2项缺膜失败。

未证实55像素截断规则本身有缺陷：后续尝试的沿岸样例在达到55前又进入完整水域，使参考点与路径重新开始；第一候选起点本身甚至并非完整水域。unit-limit-geometry与unit-limit-valid-start保存实际参考点与轨迹。没有据失败断言反推实现错误，也没有继续猜坐标、扩大55或删掉断言求绿。

## 4. 解决方式

- 仅正式分水庭雷鳗使用thunder_eel_combat.gd；隔离试玩保留原行为。沿用生命30、攻击5、55速度、110警戒、150脱战与原1秒远离判断、70攻击距离、0.8秒前摇和原捕获/奖励；不复活85出生圈。
- 完整水中保护承伤25%，最低1；离水立即失膜、取消蓄电。首次全身上岸停2.5秒；交界追击55或受阻则回水；回水沿已实际走过的短段逆序移动，不加通用寻路。完整回水凝膜1秒；普通鳗不因脱战回血。
- eel_phase、eel_left、eel_origin、eel_path保存在既有combat.actors，由Run事务保存与回滚；新概念先登记于workflow/concepts/thunder-eel-shore.zh-CN.md。未知阶段、时间类型错误和部分新字段缺失拒绝；完全缺新字段的旧档在推进时初始化，不重置生命奖励。
- 膜从已批准原件按摘要复制，主体与膜共享动作、帧、朝向、缩放和锚点；不重复乘已烘焙透明度。岸行候选沿既有审阅方案复用游动主体，移除本体水纹，以0.32秒逐帧慢蜿蜒与实际透明主体脚底贴地，不重新生图、不改变主体体型。四向拼图是受控动作预览，不冒充四条真实追击路径。
- 捕获窗、操作窗、奖励窗、地图与二次确认均复用现有组件和原收费、概率、物品。只发送Godot内部输入，普攻等待原冷却并记录真实投掷和命中，不把点击直接算作有效攻击。
