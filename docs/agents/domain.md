# 领域文档约定

## 阅读顺序

探索代码前，查阅根目录的 `CONTEXT.md`（领域说明与术语）。
提出实现或架构调整前，继续阅读 `docs/adr/` 中与本次范围相关的
ADR（架构决策记录）。

本项目采用单一领域布局：

- `CONTEXT.md`：项目领域说明与统一术语。
- `docs/adr/`：已经确认的架构决策及其原因、边界和取舍。

上述文档按需建立，本次配置不生成空白领域说明或虚构决策。
可选文档尚不存在时，继续使用现有项目资料；文件已存在但无法读取时，
报告缺口，不声称已核对。

## 术语使用

问题标题、方案、测试和报告中的领域术语，沿用 CONTEXT.md
已有定义。缺少必要定义时，按项目的概念登记规则处理，
不自行创造同义名称。

## 决策冲突

方案与已有 ADR 冲突时，明确指出对应记录、冲突内容、
建议重新审查的原因及影响范围；确认前保留原决策，不静默覆盖。
