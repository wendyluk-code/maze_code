# 招募与角色收藏契约（REC-01）

当前实现是独立工作树候选。三名新角色获批的完整立绘、技能图标已原样接入；主工作区仍需最终增量合入与集成验收。新主动和宝箱技能结算由后续票据实现，本票只记录配置、显示详情和兼容入场。

## 角色与持久状态

`scripts/characters/character_progression.gd` 的 `CHARACTERS`（统一角色配置）提供稀有度、元素、头像、完整立绘路径、技能图标、成长、主动参数及逐星增量。萨莉亚 SSR 雷，御风 SR 风，叮当 R 土，芽芽 R 草，铁山 R 土。新增角色从该表进入抽池、收藏、详情、选队及战斗栏；不在每个页面添加二选一判断。芽芽和铁山原有成长及技能保持。

配置中的 `active_rules`（主动规则）与 `star_effects`（逐星效果）是后续战斗票据的已确认输入，不代表本票已经实现技能。星级效果按顺序累计，同名键更新为新值；同类比例相加，最终伤害沿用整数取整。角色等级上限30，经验与金币突破沿用原逻辑，每5级饱腹上限加1。

`chapter_1_departure.party`（第一章剧情队伍）仍只服务原章节流程；`owned_characters_v1`（通用拥有列表）独立存储收藏，出征草稿最多4人。缺少拥有字段时只读投影合法剧情队伍，不额外授奖、不写盘。字段存在但类型错误、未知角色或重复角色时拒绝招募，不退回默认收藏。第一章入队遇到已有通用列表时仅补缺少的芽芽、铁山，不提升已拥有角色的星级。

`character_progression_v1`（角色成长）继续保存等级、经验、星级及突破次数。旧档缺少单人记录按既有规则只读显示1级1星；已经存在的坏成长记录拒绝招募。`recruitment_v1`（招募记录）保存 `stardust`（星尘余额）和 `last_results`（最近一批结果）。未知字段保存时保留。

元素显示使用 `lightning`（雷系派系名）；探索内部使用 `thunder`（雷系捕获标识）。`Progression.element`（探索元素投影）完成映射，入场存档使用后者，界面图标使用前者。不能把空元素写入探索成员。

## 招募事务

`SaveManager.recruit(count, random_source)`（招募入口）只允许单抽或十连，费用分别1000、9000金币。每次先按 SSR 10%、SR 30%、R 60%选稀有度，再在该稀有度内等概率选人；当前三名 R 各占总概率20%。十连先正常抽10次，整批没有SSR才替换末张为SSR。测试可注入随机源，正式抽取使用新随机数发生器，不改变概率。

每张按抽取顺序处理：未拥有为1星；已经拥有增加1星，最高6星；抽取前已经6星才转换100星尘。5升6不送星尘。每张结果保存自己的 `rank`（当时星级）、`kind`（首次/升星/转尘）及星尘数量，禁止用整批最终星级重画此前结果。

金币、收藏、全部成长、星尘和结果在同一个快照中一次原子保存。保存失败整体回滚，演出不启动。事务重入与界面播放期间的重复输入被拒绝。演出、关闭、跳过及重新进入页面均不发奖；进程在保存后中断，重开从已保存收藏恢复，不重放奖励事务。

未来兑换规则仅登记：1000星尘换新卡或升1星。本票不提供兑换入口或兑换事务。
