# YF-02 分水庭双人切磋历史交接

本文件保留原票据与当时验收证据。2026-10-26用户已更改战斗结束条件、动作及赠礼显示；当前行为以 [YF-04修订](yf04_revision.md) 为准，以下吃料理、对手半血及三秒锁血描述不再作为当前规格。

本票独立演示到战后三句结束并持久化 `gift_pending`（赠礼待处理）。不发料理、不解锁便当盒、不自动入队、不播放告别、不标事件完成。主工作区合入和集成验收由来源主会话执行，本工作树验证不替代该步骤。

## 基线与所有权

原始基线 `f24c4ee5200b06cbe8cc8c0b232e0f7aa8005910`，专属分支 `codex/yf-02`。经来源协调角色/招募任务停写后，将 F:/maze_code 的生产文件与未提交实现复制至隔离工作树；2656项复制前、复制后、目标与最终源哈希核对稳定。快照提交为 `23f25d2413019af5951e13a4bdc78b80ea7b6b7d`，清单 `output/yf02/snapshot.json`。只合入该提交之后的本票差异，禁止把快照整体合回。

`character_progression.gd`、`data/factions.json` 只读复用。对手读取两人1级攻击、生命和防御；不采用星级被动和成长倍率。玩家复用当前出征队伍总攻击、生命、已有成员技能及最新技能等级。普通队伍技能实现仍只支持原有锅铲/芽芽/铁山；本票不替代后续招募角色主动技能实现。

素材是用户已明确接受差异的 revision_04 全40帧，以及 style_v5 六帧原密谋待机；复制到 `assets/characters/yf02`，不改源。雷链4帧载入备用，但本场只有一个玩家，不能为显示雷链伪造额外目标。传导规则通过真实分水庭水域坐标样例验证。

## 存档与后票唯一接点

`SaveManager.yufeng_salia_record()` 返回事件只读副本；`set_yufeng_salia_record(record)` 原子保存，失败恢复完整原内存。原键为 `yufeng_salia_encounter`，版本2结构：

```json
{"version":2,"phase":"gift_pending","line":0}
```

此前阶段依次为 `unseen`（未相遇）、`intro`（战前八句，line 0至7）、`eat`（食用动画）、`question`（主角疑问）、`battle`（切磋）、`post`（战后三句，line 0至2）。battle额外保存 `start_run`（完整开战探索快照）和 `start_position`（开战脚底坐标）。post/gift_pending删除start_run；start_position可保留，是无业务效果的元数据。读取旧字符串 unseen保持未相遇，intro_pending/awaiting_battle迁移到intro第0句，绝不误作完成。坏记录诊断后回退未触发；读取不写盘。

`maze_entry.gd` 仅在 region_id=fenshui 时挂接 `yf_encounter`。它在 attach 时恢复阶段、当前句与常驻人物。battle从start_run重建独立内存切磋，双方满场初始生命、玩家开战生命和开战位置重新挑战；未改普通探索战斗，因此重试不会扣材料、金币、饱腹或奖励。三秒锁血结束后，保存post成功才进入战后对白；失败保持黑屏切磋并每秒重试，不能假推进。玩家先归零也走同一出口，绝不调用普通探索失败/丢物事务。

后票在恢复attach或运行阶段观察 `phase == "gift_pending"` 即可接入。此时第三句“……啧。算了，这些给你。”已完成、对白已隐藏、输入已释放，事件不会自行再推进。后票须把三份三星礼物及解锁凭证写入同一幂等事务，再按已确认顺序接便当盒蒙层/收取、两处入口、自动装盒。后票扩展记录阶段校验后，才可接续以下两句并最后持久化done：

1. 御风：放你便当盒了，自己看看怎么用。……走了。
2. 萨莉亚：抱歉小可爱，就当是他的赔礼吧~ 以后有机会再见哟。

本票没有预执行这两句，也没有隐藏gift_pending人物。后票须自行加入渐隐完成逻辑；当前done读取已支持且不显示人物。

## UI与锁

对白复用 `scenes/ui/dialog_box.tscn`，由事件消费E/空格/Enter/左键；禁用组件通用输入避免双推进。每句先保存再展示下一句，失败重新呈现当前句。战前/食用/疑问/战后使用 `_lock()` 与 `_unlock()`，首次记录玩家原input_locked与physics状态，退出恢复原值；不是无条件恢复为可走。事件不修改maze._busy；普通capture_flow.combat_paused通过玩家锁及模态界面判断暂停。后票调用事件锁时须配对，不能在已锁状态覆盖原值。

战斗使用capture_flow.display_run读取事件内存副本，原技能栏、Tab/数字/空格切换、左键与Shift保留；场上始终主角一个实体。事件阶段battle拦截普通死亡结算和普通战斗tick；事件结束自动读回原探索状态。角色详情、地图、确认弹窗和失焦暂停模拟，动画随状态冻结。血条复用capture_monster的组件及敌方红色填充；姓名与血条错位放置，保留原入场位置，不遮脸。黑屏由当前场景遮罩实现，失焦和弹窗不推进三秒锁血。

## 验收与复跑

统一入口 `tools/tests/yf02_run.ps1`，复制引擎到证据目录以避开Steam引擎的自包含编辑器用户目录；各场景APPDATA独立，并比对正式存档JSON指纹。依次运行Mode：import、flow、edges、seed、restore、regression、smoke；seed与restore共用同一EvidenceRoot，分别为两个独立进程。合入后传 `-ProjectRoot F:/maze_code`，使用新的EvidenceRoot，不能复用本票场景截图替代目标验收。

本树最终证据：release/flow双分辨率71项；release/edges54项；restart_seed14项、restart_restore16项。普通捕获回归ordinary_capture39项、普通技能ordinary_skills259项通过。共453项，编辑器release/import和启动release/smoke通过。所有这些运行正式存档指纹未变；仅系统证书读取环境告警。场景截图包括待机、战前、食用、实战、锁血、战后、gift_pending，已目检1152×648实战/阈值/黑屏和1280×720实战/对白/战后。最终真实左键路径以release/flow为准，早期flow_final使用伤害注入的收场检查不能作为真实命中证据。

保留首次失败：新树首次import尚无字体导入缓存而报资源错，第二次及最终复查通过；flow1测试在保存失败重试延迟后等待食用不足，补足等待后通过；flow2发现战后首次按键被旧armed状态忽略，修复锁定时重置后通过。后续截图发现普通状态校验挡住本场技能栏，已加入切磋分支并新增可见断言。最终actual_hits/flow两分辨率均通过真实左键5次有效弹道命中御风18→16→14→12→10→8，接锁血计时和战后出口；不以注入伤害替代集成。初次真实命中试射因植被岛挡射线未命中，日志保留，测试改为实际沿道路向左移动0.5秒获得合法射线后通过。修正三段后退时一处浮点类型推断编译错误已修复，失败日志保留。

稳定知识：切磋状态必须与CaptureRun普通失败/奖励事务隔离；角色详情配置不等于主动技能已实现；分水庭击退不能调用硬编码枯水渠道路的Combat.advance_hit。本票只复用既有单段12像素尺度，每段60毫秒后退、40毫秒停顿，总0.3秒三段及2秒免控。锁血3秒只固定双方NPC生命，不禁攻、不清弹道，继续对打；玩家归零仍只能走切磋出口。改战斗状态结构、地图地形、成员技能或赠礼阶段时重审并重跑本票边界与跨进程恢复。
