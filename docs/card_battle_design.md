# 卡牌战斗规则与卡面设计

本页记录用户本轮确定的规则，优先于旧文档中的卡牌等级、形态牌和战斗料理槽设计。规则版本 `no_level_v1`（无卡牌等级第一版）。本轮实现范围是设计记录、共享卡面模板、独立卡牌编辑器及审批草稿；这里的规则不等于现有战斗演示已经全部实现。芽芽、铁山的新卡牌内容由用户后续提供，旧样例只用于版式验收。

## 牌局和卡牌等级

- 对战双方是操作人（玩家、NPC等），操作人的血量归零判负；角色阵亡不等于操作人战败。
- 每个玩家每回合有2个行动点。
- 取消所有卡牌的升级机制，包括角色牌及技能牌。没有角色每回合升级一次、1至3级或对应等级解锁出牌的机制；所有界面不再显示一叶、两叶、三叶草等级标记。
- 抽到的卡牌不再受等级限制；仍须满足行动点、饱腹度、魔力、目标和效果要求。资源不足不能打出卡牌，不能先扣资源、移除手牌或产生效果再判定失败。
- 卡牌升级与冒险角色长期养成不是同一系统；本次取消战斗卡牌等级，不据此删除餐厅设施升级或冒险角色经验系统。

## 角色数值

| 数值 | 已确定规则 |
| --- | --- |
| 攻击 | 角色的攻击数值，战斗伤害按攻击力扣除敌方血量；角色卡牌可改变攻击数值和结算效果，例如免疫战斗伤害。 |
| 血量 | 角色生命值。按本次用户原文，**低于0**时阵亡，之后倒计时3回合复活。该阈值与操作人血量归零判负分别记录。 |
| 护盾 | 由角色卡牌、角色技能、食物效果获得，抵挡来自敌方角色的伤害，包括战斗与法术伤害；下个己方回合开始时消失。当前设计用词为护盾，旧实现的“护甲”不自动证明行为一致。 |
| 魔力 | 部分角色拥有，范围0至8。角色卡牌和技能可影响魔力；消耗魔力的卡牌在生效前检查，魔力不足不能使用。 |
| 饱腹度 | 每名角色有自己的上限；角色每次行动都会消耗饱腹度。卡牌要求的饱腹度不足时不能使用。 |

“饥饿值消耗”在本轮法术牌/战斗牌描述中统一记录为**饱腹度消耗**，避免出现两个方向相反的资源字段。

饱腹度为0时进入负面状态：攻击力-2，受到所有类型的伤害+2。己方回合结束时，对本回合没有主动执行任何行动的角色，默认各恢复1点饱腹度；回复量受角色效果、卡牌效果和食材效果影响。不能把“发生过被动触发”直接当作主动行动。

## 卡牌类型

| 类型 | 数值和效果 |
| --- | --- |
| 角色牌 | 每个角色有自己的基础攻击、血量、饱腹度上限与基础技能；部分角色额外有魔力。 |
| 赋形牌 | 原“形态牌”统一改名。带有自身基础攻击、血量和技能，可套在角色身上；角色阵亡时失效，复活后恢复角色牌的基础攻击、血量与技能。未指定覆盖饱腹度和魔力，模板显示沿用角色。 |
| 法术牌 | 消耗行动点与使用角色的饱腹度；有魔力消耗时另行检查。 |
| 战斗牌 | 消耗行动点与使用角色的饱腹度；有魔力消耗时另行检查。 |
| 料理 | 消耗行动点使用，具体效果由料理定义。 |

赋形牌的行动点与饱腹度具体费用尚未提供，工具预留字段，不替用户指定统一费用。角色普通出击、追加出击等行动的饱腹度消耗同样待定义。

## 战前携带料理与战内烹饪

战前顺序：选择本场携带料理 → 选择手牌/起手准备 → 进入战斗。每场只能携带一种料理；并非所有烹饪成品都有携带资格，料理分类和效果由用户后续提供。玩家可选择战斗中的使用时机，使用消耗行动点。

例如抗寒型料理可以抵消雪地战斗持续扣血；这只是用户给出的设计示例，不据此生成正式分类表、持续时间或数值。工具支持“待定 / 可携带 / 不可携带”及分类字段，分类与资格待定时允许预览但不能确认为完整设计。

携带的是允许带入本场的料理，不能自动扩展成外部携带食材。之前确定的“战斗中触发烹饪生成食材，凑齐三张合成佳肴；不明食材、运势及黑暗料理”属于另一条战内生成链路，保留设计背景，具体新牌效果仍待用户提交。不据此假定所有佳肴都有战前携带资格。

## 结算与待定边界

后续实现应先统一检查合法目标、行动点、饱腹度和魔力，再支付和结算。正例：魔力需3、实际2时，手牌、行动点、饱腹度和魔力均不改变。反例：支付行动点后才发现魔力不足，或用等级拦截已经抽到且资源足够的牌。

以下条目会改变玩法，暂不以默认值实现：

1. 角色血量恰好0时的行为：用户给定的是“低于0阵亡”，后续确认是否确实包含0血存活。
2. 复活的3回合按己方回合还是双方回合计数、扣倒计时的阶段、阵亡当回合是否计入；复活后的当前生命、饱腹度、魔力及其他状态如何恢复。
3. 每种主动行动的饱腹度消耗，包括普通出击、技能牌、追加出击、使用料理；卡牌饱腹费用是否已经包含行动消耗，避免重复扣费。
4. 饱腹初始值是否等于上限、负面状态解除时机、饥饿减攻后的攻击下限；阵亡角色是否参与回合结束的饱腹回复。
5. 护盾叠加规则、伤害抵消后余额、免疫/减伤/饥饿易伤/护盾的结算顺序；护盾是否能抵消地形等非敌方角色伤害。
6. 角色有魔力时的初始值及获得/消耗来源；每张牌的行动点、饱腹度和魔力费用。
7. 携带一种料理是否允许多份、能否不带、使用次数与持续时间，以及与战内烹饪料理之间的共用规则。
8. 赋形时当前生命如何变化、多张赋形牌的覆盖规则；本轮仅确定阵亡失效及复活恢复基础牌。

## 模板与验收

当前模板 `formal_v3`（正式素材模板第三版）继承用户确认的上半身插画、大纸面及20号正文，长文本最低18号。旧等级角标和角色底部等级位全部退出渲染；标题两侧小叶饰仅为固定装饰，不编码等级。

- 角色牌：底部保留攻击/血量，中央预留饱腹上限；勾选使用魔力后增加魔力格，上限固定8。未知值显示“—”，不伪造芽芽/铁山的新数值。
- 赋形牌：显示攻击/血量，饱腹度与可选魔力注明沿用角色；展示出牌费用。
- 法术牌/战斗牌：类型下方展示行动点、饱腹度、需要时的魔力费用，无角色攻防徽章。
- 料理：类型下方显示行动点与携带资格，分类写入审批数据。
- 战斗资源预览：角色/赋形牌额外展示护盾格及资源当前值占位；该按钮不是实际战斗模拟，不改角色状态。

真实exe验收包括五张旧内容样例无等级、赋形牌名称、资源占位、可选魔力、三种费用、料理资格、数值范围校验、审批JSON不含等级且保存新字段、长文案无重叠。详见 [卡牌数据工作流](card_workflow.md)。未来接入战斗还须验证饥饿增伤、护盾清除、魔力不足原子拒绝、阵亡/复活、赋形失效及携带料理流程；本轮不宣称这些战斗事务已实现。

## 与当前工程的差异

`scripts/card_rules.gd`、`scripts/battle/` 及旧卡牌目录仍有历史规则/数值；战斗演示和冒险者之家仍有完整原图入口，原图可能带旧等级图案。新模板不再生成等级，但这些旧入口需要后续接入新模板与新卡牌数据。本轮不改正式卡库、不覆盖用户正在运行的战斗或存档，也不把模板预览称为全游戏完成新规则迁移。
